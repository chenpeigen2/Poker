## 2. 授权委派的决策（Lead 决定，可推翻）

| ID | 决策 | 结论 | 理由与代价 |
|---|---|---|---|
| D7 | 技术栈 | `delegated` pnpm workspace + TypeScript `strict` + Vite 7 + React 19 + R3F v9 + three.js；Vitest 单测；oxlint | 与同级项目一致，边际学习成本≈0。代价：不引入 Rust/Electron，跨平台桌面能力留到 v2 |
| D8 | 工程质量 | `delegated` **零 `any`**（AST 检查脚本 `scripts/check-no-any.mjs`）、`noUncheckedIndexedAccess`、纯函数优先、模块「小而深」 | 沿用 `OneShot/AGENTS.md` 的规范。代价：写起来稍慢，换取可测与可重构 |
| D9 | 包结构 | `delegated` 四个包：`@poker/domain`（纯契约/零依赖）、`@poker/engine`（规则）、`@poker/ai`（对手）、`apps/web`（界面） | 依赖单向：`web → ai → engine → domain`。`domain` 是唯一的 seam，任何跨包通信只经过它 |
| D10 | 确定性与回放 | `delegated` **事件溯源**：`HandConfig.seed` 派生洗牌；`Action[]` 追加日志；`replay(config, actions)` 必须逐字段等于原局 | 这是「复盘」「回归测试」「破绽统计」三者共同的地基。禁止在 reducer 内使用 `Math.random()` / `Date.now()` |
| D11 | 牌力评估 | `delegated` 7 取 5 的 21 组合枚举 + 整数编码 `code` 比较；纯函数 `evaluate7` | 单挑规模下性能足够；枚举法可穷举测试、无查表文件、无外部依赖。代价：不如 TwoPlusTwo 查表快，但本项目不跑百万手模拟 |
| D12 | 下注状态机 | `delegated` 完整 HU NLHE：按钮=小盲且翻前先行动、翻后大盲先行动；min-raise 增量规则；短 all-in 不重开下注权；未跟注下注返还；单边池；摊牌分池 | 经典边界，也是最值得写成测试的地方。**不简化规则**——规则一简化，「试探」的意义就没了 |
| D13 | AI 决策 | `delegated` `Intent`（结构化意图）为唯一输出：动作 + 注额 + 牌力桶 + 意图标签 + `tellLevel` + 胜率 + 理由；评估层用有界蒙特卡洛（≤200 次，独立种子），决策层用 1-ply EV 前瞻 | 结构化意图让「读心面板 / 台词 / 档案」三处复用同一份数据；不输出裸动作 |
| D14 | 破绽设计 | `delegated` 破绽是**参数化且稳定**的：过度弃牌于 c-bet、几乎不在河牌诈唬、小注=强牌的反向 tell、连败后缩手（tilt）、行动节奏（thinkTimeMs）作为物理 tell | 「稳定」= 玩家可归纳；「参数化」= 可配置多个对手、可写属性测试验证指纹稳定 |
| D15 | 表达层与 LLM | `delegated` `ExpressionAdapter` 接口；v1 默认 `templateAdapter`（纯本地模板），`LlmAdapter` 只留接口与禁用桩 | 浏览器无 API key、无后端。LLM 是皮不是骨架；v1 零网络请求也能完整可玩。代价：v1 台词不如 LLM 惊艳 |
| D16 | 档案系统 | `delegated` 极简：3~4 个指标、只在「假设被验证/推翻」时出现反馈；假设用标签登记，样本达阈值才解锁档案卡 | 防止它退化成没人看的图表。反馈文案必须明确「成立 / 不成立」，学习必须可见 |
| D17 | 试探机制 | `delegated` **不新增任何规则**；把 check-call / 小 raise / 平跟看摊牌重新命名为「试探」，玩家可给动作打 `probe` 标记，系统记证据样本 | 同一动作两种理解，是「读人」乐趣的来源；零规则污染 |
| D18 | 持久化 | `delegated` `localStorage`：牌局记录、档案、假设、筹码；无账号、无后端、无数据库 | 单挑现金局不需要服务端 |
| D19 | 视觉资产 | `delegated` 程序化生成：Canvas 生成牌面/桌布贴图 + 简单几何体筹码；WebAudio 程序化音效（可选） | 不找外部模型，避免卡在素材上耗一周 |
| D20 | 交付顺序 | `delegated` 契约 → engine（含穷举测试）→ ai → web 垂直切片 → 集成验收 | 先把最容易错、最需要确定性的地基打牢 |
| D21 | 现金桌筹码 | `delegated` 任一方破产时**双方一起**重置为 1000 等额买入 | 只给破产方补给会造成「对手无限钱、我方筹码膨胀」，后续手牌的筹码/底池比不可比，破坏读人样本的一致性 |
| D22 | 试探如何产生证据 | `delegated` 玩家把动作标记为 `probe` 即开启一个可观察窗口（含 check-call 这类廉价探测），不要求必须真的下注 | 否则最便宜、最自然的试探方式永远拿不到证据，「假设 → 试探 → 验证」循环会退化成死路（浏览器实测暴露后修正） |
| D23 | 多对手档案 | `delegated` 每个对手一份独立 `Dossier`，切换人格不清空已读出的破绽，且预建空档案 | 换个人就清零等于惩罚玩家切换对手；观察进度应可比较 |
| D24 | 试探标记的作用域 | `delegated` `probe` 是**单次动作**标记，提交后自动复位 | 浏览器实测发现开关不复位会让后续每个动作都被记为试探（9 手记了 25 次），污染样本 |
| D25 | 复盘形态 | `delegated` 复盘驱动**同一张 3D 牌桌**（`replay()` 的 `GameState` 回传给 `PokerTable`），不另做一套渲染器 | 避免两套渲染逻辑漂移；键盘 ← → 逐步、Esc 返回实时 |
| D26 | timing tell 落地 | `delegated` `Intent.timingMs` 由人格节奏 + 决策难度确定性派生，UI 用它做思考延时并展示「偏慢/偏快」 | 让「他思考越久牌越弱」从宣传语变成可量化、可归纳的观察对象，且不破坏可复现性 |
| D27 | 假设判定可追溯 | `delegated` 每条假设保留 `HypothesisSample[]` 证据链，面板可展开逐手查看命中原因 | 「成立/不成立」若不给依据，玩家无法修正画像，学习不可见 |
| D28 | 可利用性可验证 | `delegated` `measureExploitability()` 用固定 c-bet 剥削策略量化人格，并写成测试断言「紧弱 > 跟注站」 | 「破绽可被针对」是这个项目的核心主张，必须能被测试证伪，而不是嘴上说说 |
| D29 | 交付完备度 | `delegated` 程序化 WebAudio 音效、程序化毡布/木纹/牌面贴图、代码分割、GitHub Actions CI、git 初始化 | 零外部素材与零网络请求的约束下，「质感」只能靠程序化生成；CI 把验收标准固化 |

## 4. 核心循环（把「读人」砸成机制）

```
玩家提出假设（标签登记）
  → 用 check-call / 小 raise 主动试探（花筹码买信息）
  → 观察对手反应（动作 + 注额 + 节奏 + tellLevel）
  → 本手结束得到判定反馈：假设成立 / 不成立
  → 修正画像，下一手针对性施压
```

失败模式清单（必须避开）：
1. 破绽不可归纳（CFR 的细微次优 / LLM 的随机失误）→ 读不了。
2. 参数化 Bot 被打 20 局吃成查表 → 用有界搜索 + 多对手人格 + tilt 缓解。
3. 档案变成没人看的图表 → 极简 + 只在验证时刻出现。
4. 没有判定反馈 → 玩家学不到东西，「读人」退化成玄学。

## 5. 验收标准（Definition of Done）

1. `pnpm typecheck` 全绿；`scripts/check-no-any.mjs` 零命中。
2. `pnpm test`：牌力评估穷举/对照、底池守恒不变量、回放逐字段一致、下注合法性（含短 all-in 不重开权）、AI 给定种子确定性、`Intent` 结构完整。
3. `pnpm build` 生产构建通过；`pnpm dev` 打开后能完成一整手（发牌→四条街→摊牌/弃牌→结算→下一手）。
4. 一手牌结束后：档案面板出现「假设成立/不成立」反馈；复盘视图能逐步回放该手。
5. 全程零网络请求即可完整可玩（验证 D15 的优雅降级）。
